# Tenancy model — Python interface

Companion to [2.tenancy-model.md](2.tenancy-model.md). That document explains how tenancy is stored. This one is the **contract other modules use**: import `AuthController`, call methods, pass kwargs, read the envelope.

Python does not enforce public vs private. Treat everything on `AuthController` that is not prefixed `_` as callable. This page lists the tenancy surface. Identity (`get_current_user`), the access graph (`create_rel`, `assign_team_tools`, …), and `authorize()` / the auth tree are other interfaces.

## 1. How to get a controller

```python
from renglo.auth.auth_controller import AuthController
from renglo.common import load_config  # handlers outside Flask

auc = AuthController(config=load_config())
# or, inside a Flask-backed class that already has config:
# self.AUC = AuthController(config=self.config)
```

`config` must include the usual Core keys (`DYNAMODB_ENTITY_TABLE`, `DYNAMODB_REL_TABLE`, Cognito, …). Callers do not pass a table client.

Typical consumer:

```python
class SomeHandler:
    def __init__(self):
        config = load_config()
        self.AUC = AuthController(config=config)

    def run(self, payload):
        portfolio = payload["portfolio"]
        org = self.AUC.get_entity("org", portfolio_id=portfolio, org_id=payload["org"])
        if not org.get("success"):
            return org
        ...
```

## 2. Response envelope

Almost every method returns a **dict**, not an exception, for expected failures:

```python
{
    "success": True | False,
    "message": str,
    "status": int,       # HTTP-ish: 200, 400, 404, 500
    "document": ...,     # present on many successes; sometimes on failures
}
```

Always branch on `success` (or `status == 200`). Do not assume `document` exists.

| `status` | Typical meaning |
|---|---|
| `200` | Ok |
| `400` | Missing kwargs, nothing to update, validation |
| `404` | Entity not found (`get_entity`) |
| `500` | Required id kwargs missing on `get_entity` |

Funnels that fail mid-way return the **failed step’s** envelope (not a wrapped `{success, document: transaction}`). On full success, `document` is a **list of step envelopes**.

## 3. Entity document (what you get back)

On success, `get_entity` / `create_entity` / `update_entity` put this object in `document`. Callers should treat these fields as the public record. Do not build `index` or `irn` yourself; pass ids in kwargs.

| Field | Type | Notes |
|---|---|---|
| `_id` | str | **The id you store and pass back** (`portfolio_id`, `org_id`, …) |
| `type` | str | `"user"` \| `"portfolio"` \| `"org"` \| `"team"` \| `"tool"` |
| `name` | str | Display name |
| `about` | str | Optional |
| `handle` | str | Org/tool short name; may be `""` |
| `email` | str | Used on users |
| `slot_a` | str | Last name on users |
| `slot_b` … `slot_e` | str | Optional extras |
| `location` | str | Optional |
| `owner_id` | str | Creator `user_id` when provided at create |
| `tags` | `dict[str, list[str]]` | Empty `{}` if unset |
| `roles` | `list[str]` | **Tools only** — catalog of assignable roles |
| `is_active` | bool | Set `True` on create |
| `added`, `modified`, `last_login` | ISO str | Timestamps |
| `last_ip`, `language` | str | Set if you passed `ip` / `lan` |
| `raw_id`, `index`, `irn` | str | Present; ignore unless you are Core |

Minimal example:

```json
{
  "success": true,
  "message": "Entity found",
  "status": 200,
  "document": {
    "_id": "c0ffee12aabb",
    "type": "org",
    "name": "Downtown Site",
    "handle": "DS",
    "about": "",
    "tags": {},
    "is_active": true
  }
}
```

## 4. Ids

| Kind | Length | Who issues it | How you obtain it |
|---|---|---|---|
| `user_id` | 9 hex chars | Identity (`get_current_user()`), not tenancy create | Do not invent; hash of Cognito username |
| `portfolio_id`, `org_id`, `team_id`, `tool_id` | 12 hex chars | `create_entity` / funnels | `response["document"]["_id"]` or funnel `document[n]["document"]["_id"]` |

Pass ids as **keyword arguments** named `user_id`, `portfolio_id`, `org_id`, `team_id`, `tool_id`. Nested types always need the parent `portfolio_id` **and** the child id.

Sentinel org id for portfolio-scoped work: `AuthController.PORTFOLIO_SCOPE_ORG` → `"_all"`. That is **not** an entity. `get_entity("org", org_id="_all", ...)` will 404.

```python
if AuthController.is_portfolio_scope_org(org):
    # portfolio-wide ring; not a row you can get_entity
    ...
```

## 5. Read

### `get_entity(type, **kwargs) -> dict`

Fetch one document.

| `type` | Required kwargs |
|---|---|
| `"user"` | `user_id` |
| `"portfolio"` | `portfolio_id` |
| `"org"` | `portfolio_id`, `org_id` |
| `"team"` | `portfolio_id`, `team_id` |
| `"tool"` | `portfolio_id`, `tool_id` |

Missing required kwargs → `success=False`, `status=500`, `message="Some parameters are missing"`.  
Missing row → `status=404`.  
Found → `document` is the entity.

```python
tool = auc.get_entity("tool", portfolio_id=portfolio, tool_id=tool_id)
if not tool["success"]:
    return tool
handle = tool["document"]["handle"]
roles = tool["document"].get("roles") or []
```

### `list_entity(type, **kwargs) -> dict`

List children (or, for portfolios, the caller’s tenants).

| `type` | Required kwargs | `document` on success |
|---|---|---|
| `"org"` | `portfolio_id` | `{ "items": [entity, …], "lastkey": … }` |
| `"team"` | `portfolio_id` | same |
| `"tool"` | `portfolio_id` | same |
| `"portfolio"` | `user_id` | **Not** entity list — see below |
| `"app"` | `team_id` | Leftover; do not use |

`items` are full entity documents. Default page size is 50. `lastkey` is a pagination cursor or omitted/`None`; `list_entity` does not accept `limit` / `lastkey` from the controller today.

```python
listed = auc.list_entity("tool", portfolio_id=portfolio)
items = ((listed or {}).get("document") or {}).get("items") or []
for item in items:
    if item.get("handle") == "data":
        tool_id = item["_id"]
```

**`type="portfolio"`** does not return portfolio entities. `document` is a list of relationship-list responses (one per team the user belongs to). Prefer `GET /_auth/tree` or walk `document[i]["document"]["items"][j]["rel"]` for portfolio ids, then `get_entity("portfolio", portfolio_id=...)`. New callers should not depend on this shape if they can use the tree.

### `get_team_users(*, user_id, team_id) -> dict`

Roster of a team, hydrated from user entities.

**In:** `user_id` (caller, must be a member), `team_id` (not composed with portfolio).

**Out success:** `document` is a **dict keyed by user id**:

```json
{
  "success": true,
  "message": "Users in the team",
  "status": 200,
  "document": {
    "3e3417d7e": {
      "user_id": "3e3417d7e",
      "name": "Ada",
      "last": "Lovelace",
      "email": "ada@example.com"
    }
  }
}
```

If `user_id` is not on the team → `400` `"User is not in this team"`. Users whose entity is missing are skipped.

## 6. Write a single entity

These methods touch **one row**. They do not add the creator to a team, do not write `team:portfolio`, and do not install grants. Onboarding handlers often use them and then call the access-graph API themselves. HTTP `/_auth` create routes use funnels instead ([§7](#7-funnels-create--remove-with-side-effects)).

### `create_entity(type, **kwargs) -> dict`

**Required by type**

| `type` | Required | Typical optional |
|---|---|---|
| `"user"` | `user_id` | `name`, `slot_a`, `email`, `ip`, `lan` |
| `"portfolio"` | — | `name`, `about`, `user_id` (stored as `owner_id`), `tags` |
| `"org"` | `portfolio_id` | `name`, `handle`, `about`, `user_id`, `tags` |
| `"team"` | `portfolio_id` | `name`, `about`, `user_id`, `tags` |
| `"tool"` | `portfolio_id` | `name`, `handle`, `about`, `roles` (`list[str]`), `user_id`, `tags` |

Optional envelope kwargs (all types): `name`, `about`, `handle`, `location`, `email`, `slot_a`–`slot_e`, `user_id`, `ip`, `lan`, `tags` (must be a `dict` or it is stored as `{}`).

**Out success:** `document` is the **created entity** (including new `_id`). Same envelope as `get_entity`.

```python
created = auc.create_entity(
    "tool",
    portfolio_id=portfolio,
    name="Data",
    handle="data",
    about="Data explorer",
    roles=["viewer", "editor", "admin"],
    user_id=user_id,
)
tool_id = created["document"]["_id"]
```

`roles` is stored only when `type == "tool"`. Values are normalized to a unique list of non-empty strings.

### `update_entity(type, **kwargs) -> dict`

Loads the entity with the same id kwargs as `get_entity`, then merges `payload`.

**Required:** id kwargs for `type`, plus **`payload`** (a `dict` of fields to overwrite).

```python
auc.update_entity(
    "tool",
    portfolio_id=portfolio,
    tool_id=tool_id,
    payload={"roles": ["operator", "admin"]},
)
```

| Behavior | Detail |
|---|---|
| Missing entity, not user | `400` `"Nothing to update."` |
| Missing **user** | Runs `create_user_funnel` (upsert) |
| `payload["tags"]` | Sanitized to `dict[str, list[str]]` |
| Other payload keys | Written onto the document as-is (including `roles` on tools) |
| User + `name` / `slot_a` / `email` in kwargs | Fills those fields only if currently empty |

**Out success:** `document` is the full updated entity.

Omitting `payload` raises `KeyError`. Nested HTTP routes build `payload` for you; Python callers must pass it.

### `unlink_entity(**doc) -> dict`

Soft-delete: the entity is no longer returned by `get_entity` / `list_entity`.

**In:** the **full entity document** from `get_entity` (must include `index` and `_id`). Not ids alone.

```python
got = auc.get_entity("team", portfolio_id=pid, team_id=tid)
if got["success"]:
    auc.unlink_entity(**got["document"])
```

Prefer `remove_team_funnel` / `remove_tool_funnel` when you also need related edges cleared. `unlink_entity` does not delete relationships.

### `create_user_funnel(**kwargs) -> dict`

Creates a user entity (`create_entity("user", ...)`). Requires `user_id`. Success `document` is a **one-element transaction list**.

Usually you do not call this; `update_entity("user", ...)` does when the row is missing. See identity docs for profile + Cognito.

### `update_user_profile(*, user_id, cognito_username, first_name, last_name) -> dict`

Identity + user entity. Both names required. Not a general entity update.

## 7. Funnels (create / remove with side effects)

Funnels are the operations you call when you want the **same outcome as `/_auth`**, not a bare row.

Success: `{success, message, status: 200, document: [step, step, …]}`.  
Each `step` is itself an envelope. New ids:

| Funnel | Where to read the new id |
|---|---|
| `create_portfolio_funnel` | Portfolio: `document[0]["document"]["_id"]`; Admin team: `document[1]["document"]["_id"]` |
| `create_org_funnel` | `document[0]["document"]["_id"]` |
| `create_team_funnel` | `document[0]["document"]["_id"]` |
| `create_tool_funnel` | `document[0]["document"]["_id"]` |

Failure: the failed step dict (`success=False`), not a partial transaction list.

Funnels are **not atomic**. A failure after the first step can leave a portfolio without an Admin team (etc.).

### `create_portfolio_funnel(**kwargs) -> dict`

**Expect:** `user_id` (creator), `name` (and optional `about`, `ip`, `lan`, `tags`).

**Also does:** creates team `Admin`, attaches it to the portfolio, adds `user_id` as a member.

**Does not:** create an org or install a tool.

```python
result = auc.create_portfolio_funnel(name="Acme", about="Acme workspace", user_id=user_id)
if not result["success"]:
    return result
portfolio_id = result["document"][0]["document"]["_id"]
```

Calling `create_entity("portfolio")` instead skips Admin + membership. That is what some onboarding handlers do; they then create teams/rels themselves.

### `create_org_funnel(**kwargs) -> dict`

**Required:** `name`, `portfolio_id`. Optional: `user_id`, `about`, `tags`, …

**Also does:** sets `handle` via `generate_handle(name)` (uppercase letters and digits only, max 10 chars; `"warehouse"` → `""`).

**Does not:** grant any team access. The org exists but is inactive until access-graph grants.

```python
org = auc.create_org_funnel(name="Downtown Site", portfolio_id=portfolio_id, user_id=user_id)
org_id = org["document"][0]["document"]["_id"]
```

Missing `name` or `portfolio_id` → `400` `"Missing attributes"`.

### `create_team_funnel(**kwargs) -> dict`

**Required:** `name`, `portfolio_id`. **Expect `user_id`** (first member).

**Also does:** places the team in the portfolio and adds `user_id` to the team.

**Does not:** assign tools, roles, or orgs.

```python
team = auc.create_team_funnel(name="Editors", portfolio_id=portfolio_id, user_id=user_id)
team_id = team["document"][0]["document"]["_id"]
```

### `create_tool_funnel(**kwargs) -> dict`

Same inputs as `create_entity("tool", ...)`. Only creates the tool row. HTTP `/_auth/portfolios/{id}/tools` additionally restricts `name` to the Data/Schd catalog **before** calling this; the funnel itself does not.

### `remove_team_funnel(**kwargs) -> dict`

**Required:** `portfolio_id`, `team_id`.

Unlinks the team entity and removes placement/membership (and legacy `team:org`) edges. Tool grant edges may remain. Missing team → `400` `"Team not found"`.

### `remove_tool_funnel(**kwargs) -> dict`

**Required:** `portfolio_id`, `tool_id`.

Unlinks the tool entity only. Grant edges may remain. Missing tool → `400` `"Tool not found"`.

### `remove_org_funnel(**kwargs) -> dict`

**Stub.** Returns `success=True`, `document=[]` and does **not** delete the org. Do not call this expecting removal.

### Membership funnels (team as container)

These change **who is on a team**, not the team document. They belong to the access graph but are often called next to tenancy create:

| Method | Required kwargs | Effect |
|---|---|---|
| `add_user_to_team_funnel` | `user_id`, `team_id` | Adds membership both directions |
| `remove_user_from_team_funnel` | `user_id`, `team_id` | Removes both directions |

HTTP refuses removing yourself; these methods do not.

## 8. Helpers

### `generate_handle(name) -> str`

```python
auc.generate_handle("Acme Building 12")  # "AB12"
auc.generate_handle("First Org")         # "FO"
auc.generate_handle("warehouse")         # ""
```

Used by `create_org_funnel`. If you `create_entity("org", handle=...)` you pass the handle yourself.

### `AuthController.PORTFOLIO_SCOPE_ORG`

Class attribute `"_all"`.

### `AuthController.is_portfolio_scope_org(org) -> bool`

True when `str(org).strip() == "_all"`.

## 9. What this interface does not do

| Need | Use instead |
|---|---|
| Who is the caller? | `get_current_user()` — [identity](1.identity-and-session.md) |
| Grants, invites, `user:team` except via funnels | [access graph](3.access-graph.md) — `create_rel`, `assign_team_tools`, … |
| May this user use this org/tool? | `authorize()` / auth tree |
| HTTP `/_auth/portfolios/...` | `renglo-api` routes wrapping these methods |
| Refresh S3 auth tree | `refresh_tree()` after you change entities/rels (HTTP routes do this; library callers often should too) |

`create_entity` / `update_entity` / `unlink_entity` do **not** refresh the auth tree. `/_auth` routes call `refresh_tree()` after mutating funnels. If your handler changes tenancy and the console reads `/_auth/tree`, call `auc.refresh_tree()` (requires a current user) or the equivalent HTTP refresh.

## 10. Call patterns

### Look up a tool by handle (extension onboarding)

```python
listed = self.AUC.list_entity("tool", portfolio_id=portfolio)
for item in ((listed.get("document") or {}).get("items") or []):
    if str(item.get("handle") or "") == "schd":
        return item["_id"]
created = self.AUC.create_entity(
    "tool",
    portfolio_id=portfolio,
    name="Schd",
    handle="schd",
    roles=["operator", "admin"],
)
return created["document"]["_id"]
```

### Create a tenant the `/_auth` way

```python
user_id = auc.get_current_user()
port = auc.create_portfolio_funnel(name="Acme", user_id=user_id)
pid = port["document"][0]["document"]["_id"]

org = auc.create_org_funnel(name="Downtown Site", portfolio_id=pid, user_id=user_id)
oid = org["document"][0]["document"]["_id"]

team = auc.create_team_funnel(name="Editors", portfolio_id=pid, user_id=user_id)
tid = team["document"][0]["document"]["_id"]
```

### Create rows only (onboarding that owns its own rels)

```python
p = auc.create_entity("portfolio", name=name)
pid = p["document"]["_id"]
t = auc.create_entity("team", name=name, portfolio_id=pid)
# then auc.create_rel("team:portfolio", team_id=t["document"]["_id"], portfolio_id=pid)
```

### Rename / patch

```python
auc.update_entity(
    "org",
    portfolio_id=pid,
    org_id=oid,
    payload={"name": "Uptown", "tags": {"region": ["north"]}},
)
```

## 11. Quick reference

| Method | You pass | You get on success |
|---|---|---|
| `get_entity(type, **ids)` | type + ids | `document`: one entity |
| `list_entity("org"\|"team"\|"tool", portfolio_id=)` | portfolio | `document.items`: entities |
| `list_entity("portfolio", user_id=)` | user | list of rel-query blobs (awkward) |
| `get_team_users(user_id=, team_id=)` | caller + team | `document`: `{user_id: {name, last, email}}` |
| `create_entity(type, **fields)` | type + fields | `document`: new entity (`_id` set) |
| `update_entity(type, payload=, **ids)` | ids + payload | `document`: updated entity |
| `unlink_entity(**entity_doc)` | full document | delete-step envelope |
| `create_portfolio_funnel(user_id=, name=)` | creator + name | `document[]` steps; `[0]` portfolio |
| `create_org_funnel(name=, portfolio_id=)` | | `document[0]` org (`handle` set) |
| `create_team_funnel(name=, portfolio_id=, user_id=)` | | `document[0]` team + membership |
| `create_tool_funnel(...)` | same as `create_entity("tool")` | `document[0]` tool |
| `remove_team_funnel(portfolio_id=, team_id=)` | | transaction list |
| `remove_tool_funnel(portfolio_id=, tool_id=)` | | transaction list |
| `remove_org_funnel(...)` | anything | success **without deleting** |
| `generate_handle(name)` | str | str |
| `is_portfolio_scope_org(org)` | org id | bool |

Implementation, IRNs, and Dynamo keys: [2.tenancy-model.md](2.tenancy-model.md).
