# Renglo Auth — `AuthController` public interface

This is the document for **using** Renglo Auth from other modules: what the service is, the ideas it is built on, and every public method on `AuthController`. It does not describe DynamoDB keys, Cognito API names, or S3 object layout. Those live in the topic docs ([identity](1.identity-and-session.md), [tenancy](2.tenancy-model.md), [access graph](3.access-graph.md)).

Python does not enforce public vs private. **Do not call methods whose names start with `_`.** Do not import `AuthModel` from application code; the controller is the service.

```python
from renglo.auth.auth_controller import AuthController
from renglo.common import load_config

auc = AuthController(config=load_config())
```

## 1. What Renglo Auth is

Renglo Auth answers three questions:

| Question | How |
|---|---|
| **Who is calling?** | A Cognito user, mapped to a stable `user_id`, optionally with a user profile entity |
| **What containers exist?** | Five **entity** types: user, portfolio, org, team, tool |
| **What may they do?** | **Relationships** (membership and grants) compiled into an **auth tree**, then **`authorize()`** |

Other Core modules (data, files, chat, extensions) should:

1. Construct `AuthController` with the same `config`
2. Resolve the caller with `get_current_user()`
3. Gate work with `authorize(portfolio, org, …)` (or `@authorize` on a class that has `self.AUC`)
4. Load names and ids with `get_entity` / `list_entity` when they need documents
5. Mutate tenancy only through funnels or entity/rel methods, then **`refresh_tree()`** so later `authorize()` sees the change

They should not reimplement Cognito, Dynamo, or tree assembly.

## 2. A running example

Throughout this page:

| Role | Name | Id (illustrative) |
|---|---|---|
| Person | Ada | `user_id` = `3e3417d7e` |
| Tenant | Acme | `portfolio_id` = `a1b2c3d4e5f6` |
| Site | Downtown | `org_id` = `c0ffee12aabb` |
| Group | Editors | `team_id` = `f6e5d4c3b2a1` |
| Installed app | Data | `tool_id` = `0da7a0001111`, `handle` = `data` |

Ada is allowed to **edit Data in Downtown** when she is on Editors, Editors may use Data, Editors has the `editor` role on Data, and Editors may use Data in Downtown. That last grant is what makes Downtown **active** for her.

## 3. Configuration

Pass a `dict` (usually `load_config()` / Flask `renglo_config`). Keys are uppercase strings. Missing keys fail at call time, not at construct time (tables default to placeholder names).

### Always needed (entities and relationships)

| Key | Purpose |
|---|---|
| `DYNAMODB_ENTITY_TABLE` | Entity documents (users, portfolios, orgs, teams, tools) |
| `DYNAMODB_REL_TABLE` | Relationship edges |

### Identity and Cognito admin (lookup, invite accept, profile sync)

| Key | Purpose |
|---|---|
| `COGNITO_REGION` | Cognito + fallback SES region |
| `COGNITO_USERPOOL_ID` | User pool |
| `COGNITO_APP_CLIENT_ID` | App client (invite challenge helper; console sign-in uses it too) |

JWT validation for HTTP is Flask-Cognito on the API, not these keys on the controller. The controller only needs Cognito to **admin**-create users, look up by email, and update name attributes.

### Auth tree (required for `authorize`, `get_cached_tree`, `refresh_tree`)

| Key | Purpose |
|---|---|
| `S3_BUCKET_NAME` | Cached tree at `auth/tree/{user_id}` |

Without this, `get_cached_tree` / `authorize` return `500` `"S3_BUCKET_NAME not configured"` (unless the tree can still be rebuilt in-process after a miss — upload may fail; `authorize` still needs a successful tree load).

### Team invites (email + hash)

| Key | Purpose |
|---|---|
| `SECRET_KEY` | Invite code material |
| `FROM_EMAIL` | SES From; required to send |
| `FE_BASE_URL` | Console base for `/invite?...` links in production |
| `INVITE_FE_BASE_URL` | Overrides console URL (local Vite) |
| `WL_NAME` | Product name in the email (default `"Renglo"`) |
| `AWS_REGION` or `AWS_DEFAULT_REGION` | SES region if not Cognito region |

AWS credentials come from the environment / instance role, not this dict.

### Optional / unused on the constructor

`tid` and `ip` on `AuthController(config, tid=..., ip=...)` are accepted and ignored.

## 4. Response envelope

Most methods return a **dict** instead of raising for expected failures:

```python
{
    "success": True,          # or False
    "message": "Entity found",
    "status": 200,            # 200, 400, 401, 403, 404, 410, 500, 501
    "document": { ... },      # omitted on many errors
}
```

**Always check `success`.** Do not assume `document` is present.

Exceptions:

- `get_current_user` returns a **string or `None`**, not an envelope
- `generate_handle` / `generate_numeric_hash` / `generate_invite_hash` / `generate_ttl` / `is_portfolio_scope_org` / `user_portfolios` / `is_user_team_*` return plain values
- `resolve_tool_roles` returns a **list of strings**
- `normalize_auth_tree` returns a **tree dict**
- `refresh_tree` on S3 upload failure may return a **tuple** `(envelope, 500)` — treat that as failure

Funnels on **full success** set `document` to a **list of step envelopes**. On **mid-funnel failure** they return that step’s envelope (not a list). New ids: `result["document"][0]["document"]["_id"]` for most create funnels; portfolio funnel also creates Admin at `[1]`.

## 5. Concepts

### 5.1 Identity

A person signs in with Cognito. Renglo’s **`user_id`** is nine hex characters derived from the Cognito username. That id is the join key everywhere.

The **user entity** is a profile document (`name`, last name in `slot_a`, `email`, …). It is created lazily (`update_entity("user")` or invite accept). It is **not** nested under a portfolio. Access to a tenant is only via **team membership**.

`get_current_user()` reads JWT claims (Flask), or an invocation override (Lambda/Docker). See [identity](1.identity-and-session.md).

### 5.2 Entities (what exists)

An **entity** is a named record with a shared field layout. There are **five types**:

```
                    User  (global person)
                      |
                      |  member of (relationships, not nesting)
                      v
                 Portfolio  (the tenant / workspace)
                 /    |    \
              Team   Org   Tool
           (groups) (sites) (installed extension
            get all          instance + role catalog)
            grants)
```

| Type | What it is | Parent |
|---|---|---|
| `user` | Person | None (global) |
| `portfolio` | Tenant | None (global) |
| `org` | Operating unit (building, brand, site). Application data is scoped `(portfolio, org, ring)` | Portfolio |
| `team` | Group of users. **Grants attach to teams, never to users** | Portfolio |
| `tool` | Installed copy of a system extension (`data`, `schd`, …) plus a **catalog** of role names | Portfolio |

**`_all` is not an entity.** It is a sentinel org id (`AuthController.PORTFOLIO_SCOPE_ORG`) meaning “portfolio-scoped,” not “any org.” `get_entity("org", org_id="_all")` will not find a row.

All five types share the same document fields (`_id`, `name`, `about`, `handle`, `tags`, `type`, timestamps, …). Tools add `roles` (list of strings). Users use `email` and `slot_a` (last name). Nested types are always addressed as **`(portfolio_id, child_id)`**.

Ids: users 9 hex chars (from Cognito); portfolio/org/team/tool 12 hex chars (issued at create). Store `_id` and pass it back; do not invent ids except `user_id` from identity.

### 5.3 Relationships (how they attach)

Entities do not contain nested member lists or grant arrays. **Relationships** are separate edges: one source (encoded in the rel type + source id) to one target id.

Allowed `reltype` values and the kwargs you pass:

| `reltype` | You pass | Meaning |
|---|---|---|
| `user:team` | `user_id`, `team_id` | Ada is on Editors |
| `team:user` | `user_id`, `team_id` | Inverse roster (always write **both**) |
| `team:portfolio` | `team_id`, `portfolio_id` | Editors belongs to Acme |
| `team:tool` | `team_id`, `tool_id` | Editors may use Data |
| `team/tool:role` | `team_id`, `tool_id`, `role_id` | Editors has role `editor` on Data |
| `team/tool:org` | `team_id`, `tool_id`, `org_id` | Editors may use Data **in Downtown** (or `_all`) |
| `team:org` | `team_id`, `org_id` | Legacy; **not** what `authorize` uses for org access |
| `email:hash:ttl` | `email`, `hash`, `ttl` | Pending invite challenge |
| `hash:team` | `hash`, `team_id` | Invite code → team |

There is no `user:portfolio` or `user:tool`. Ada reaches Acme only `user → team → portfolio`. Ada reaches Data in Downtown only through team grants.

A relationship **document** is just `{ "index": "...", "rel": "<target id>" }`. Callers usually only need `rel`.

### 5.4 The auth tree (what `authorize` reads)

The **auth tree** is a **per-user snapshot** of every portfolio Ada can see: team names, org names, installed tools, which orgs are **active**, and which roles she has on which tool in which org.

It exists so every request does not re-walk the graph. `authorize()`, `resolve_tool_roles()`, and the console (`GET /_auth/tree`) all depend on it. **If you change entities or rels, call `refresh_tree()`** (or the HTTP tree refresh) so the next `authorize()` is not stale.

Shape (abbreviated):

```json
{
  "user_id": "3e3417d7e",
  "portfolios": {
    "a1b2c3d4e5f6": {
      "portfolio_id": "a1b2c3d4e5f6",
      "name": "Acme",
      "teams": {
        "f6e5d4c3b2a1": {
          "team_id": "f6e5d4c3b2a1",
          "name": "Editors",
          "tools_access": ["0da7a0001111"],
          "tools": {
            "0da7a0001111": {
              "roles": ["editor"],
              "orgs": ["c0ffee12aabb"]
            }
          }
        }
      },
      "orgs": {
        "c0ffee12aabb": {
          "org_id": "c0ffee12aabb",
          "name": "Downtown Site",
          "handle": "DS",
          "active": true,
          "tools": ["0da7a0001111"]
        },
        "_all": {
          "org_id": "_all",
          "name": "ALL",
          "active": false,
          "portfolio_scope": true,
          "tools": []
        }
      },
      "tools": {
        "0da7a0001111": {
          "tool_id": "0da7a0001111",
          "name": "Data",
          "handle": "data",
          "roles": ["viewer", "editor", "admin"]
        }
      }
    }
  }
}
```

`orgs[id].active` is true when some team of this user has `team/tool:org` for that org. An org entity can exist and still be inactive.

`tools[].roles` on the portfolio is the **catalog**. `teams[].tools[].roles` are **assigned** roles.

### 5.5 Authorization

`authorize(portfolio, org, resource="org"|"tool", tool_id=...)` loads Ada’s tree and returns allow/deny plus **roles**.

- `resource="org"`: Downtown must be `active` (or `_all` with at least one active real org).
- `resource="tool"`: also a team grant of that tool in that org. `tool_id` may be a tool id **or** handle (`"data"`).
- `action` is reserved; it is not enforced yet.

Roles are the union across Ada’s teams for that tool+org. Extensions should trust `result["roles"]` (or `payload["_auth_roles"]` from `@authorize`), never a client-supplied role list.

### 5.6 Funnels vs single writes

**`create_entity` / `create_rel`** write one record.

**Funnels** (`create_portfolio_funnel`, …) perform several steps (entity + membership, invite + email, …). HTTP `/_auth` uses funnels. Some onboarding handlers call `create_entity` and then `create_rel` themselves. Choose deliberately: a bare `create_entity("portfolio")` does **not** create Admin or membership.

Funnels are not atomic. A failure after step 1 can leave a partial tenant.

## 7. Identity

### `get_current_user(jwt_claims=None) -> str | None`

**In:** optional claims dict (same shape as a Cognito JWT payload).

**Out:** 9-char `user_id`, or `None` if unauthenticated.

Precedence: `jwt_claims` argument → `set_invocation_user` → `set_invocation_jwt_claims` → Flask JWT → `None`.

```python
user_id = auc.get_current_user()
if not user_id:
    return {"success": False, "message": "Authentication required", "status": 401}
```

---

### `set_invocation_user(user_id)`

**In:** Renglo `user_id` string.

**Out:** none. Pins identity for this instance (webhooks, tests). Wins over JWT until you set another value (there is no explicit clear except constructing a new controller).

---

### `set_invocation_jwt_claims(jwt_claims)`

**In:** claims dict or `None`. External handlers receive `_jwt_claims` in the payload; `apply_handler_invocation_context` calls this. Pass `None` on warm Lambdas so the previous caller is not reused.

**Out:** none. `get_current_user()` hashes `cognito:username` or `username`.

---

### `get_user_id(email) -> dict`

**In:** `email` (str).

**Out:** envelope. On success, `document` includes Cognito ids plus `user_id`.

Looks up the pool by email. **Do not expose over HTTP.** The derived `user_id` hashes Cognito **`sub`**, which can differ from `get_current_user()` (username hash) if username ≠ `sub`. Used when inviting someone already in the pool.

---

### `update_user_profile(*, user_id, cognito_username, first_name, last_name) -> dict`

**In:** keyword-only. Both names required (non-empty after strip).

**Out:** envelope. Updates the user entity and Cognito given/family name. If Cognito fails after the database write, `success` is false and `message` says the DB write already happened.

```python
auc.update_user_profile(
    user_id=user_id,
    cognito_username="ada@example.com",
    first_name="Ada",
    last_name="Lovelace",
)
```

## 8. The auth tree

### `get_tree_full(user_id=...) -> dict`

**In:** `user_id` kwarg.

**Out:** `{success, status: 200, document: <tree>}`. Walks membership and grants, hydrates names. Always injects `_all` via `normalize_auth_tree`.

Use when you must rebuild. Prefer `get_cached_tree` / `authorize` on the request path.

---

### `get_cached_tree(user_id) -> dict`

**In:** `user_id` (positional). Empty → `401` `"User identity required"`.

**Out:** envelope; `document` is the tree. Extra key `cached` (bool) when served from the in-process cache.

Order: instance cache → S3 → rebuild with `get_tree_full` and write S3. Requires `S3_BUCKET_NAME`.

This is what `authorize` uses.

---

### `refresh_tree() -> dict | tuple`

**In:** none. Uses `get_current_user()`.

**Out:** same as `get_tree_full`, and writes S3 + instance cache. If S3 upload fails: `({success: False, message, status: 500}, 500)`.

Call after you mutate entities or rels **as the same user whose tree must update**. HTTP `/_auth` mutating routes call this. Handlers that change grants for *another* user do not refresh that other user’s tree unless you rebuild for their `user_id` (there is no `refresh_tree(user_id=)`); `get_tree_full` + S3 is the rebuild path.

---

### `normalize_auth_tree(tree) -> dict`

**In:** tree dict (mutates portfolio nodes in place).

**Out:** the same object with `_all` on every portfolio.

Call if you loaded a raw tree (for example JSON from S3) outside `get_cached_tree`.

## 9. Authorization

### `authorize(portfolio, org, *, resource="org", action="access", tool_id=None, user_id=None) -> dict`

**In:**

| Argument | Required | Meaning |
|---|---|---|
| `portfolio` | yes | Portfolio id |
| `org` | yes | Org id or `"_all"` |
| `resource` | no | `"org"` (default) or `"tool"` |
| `action` | no | Ignored today; reserved |
| `tool_id` | for tool checks / roles | Tool id or handle |
| `user_id` | no | Defaults to `get_current_user()` |

**Out:**

```python
# allow
{
    "success": True,
    "message": "Authorized",
    "status": 200,
    "user_id": "3e3417d7e",
    "roles": ["editor"],       # empty if no tool_id / no assignments
    "tool_id": "0da7a0001111", # resolved id, or None
}

# deny examples
{"success": False, "message": "Authentication required", "status": 401, "user_id": None, "roles": []}
{"success": False, "message": "Access denied to organization", "status": 403, "user_id": "...", "roles": []}
{"success": False, "message": "Access denied to tool", "status": 403, "user_id": "...", "roles": []}
{"success": False, "message": "Authorization for resource 'x' is not implemented", "status": 501, ...}
```

```python
gate = auc.authorize(portfolio, org, resource="tool", tool_id="data")
if not gate["success"]:
    return gate
if "editor" not in gate["roles"] and "admin" not in gate["roles"]:
    return {"success": False, "message": "Editor role required", "status": 403}
```

Controllers with `self.AUC` can use `@authorize()` / `@authorize(resource="tool", tool_id_param="extension")` from `renglo.auth.authorize` instead of calling this by hand.

---

### `require_org_access(portfolio, org, user_id=None) -> dict`

Same as `authorize(..., resource="org", action="access")`.

---

### `resolve_tool_roles(portfolio, org, tool_id, user_id=None) -> list[str]`

**In:** same ids as authorize; `tool_id` may be a handle.

**Out:** list of role strings (possibly empty). Does **not** tell you whether access is denied — empty can mean no roles or failed tree. Prefer `authorize` when you need allow/deny.

```python
roles = auc.resolve_tool_roles(portfolio, org, "data")
# ["editor", "viewer"]
```

## 10. Entities

Shared **entity document** (success `document` of get/create/update):

| Field | Notes |
|---|---|
| `_id` | Id you persist and pass around |
| `type` | `user` \| `portfolio` \| `org` \| `team` \| `tool` |
| `name`, `about`, `handle` | Strings; handle often used for tools/orgs |
| `email`, `slot_a`–`slot_e`, `location` | Optional; `slot_a` = last name on users |
| `owner_id` | Creator `user_id` if you passed it |
| `tags` | `dict[str, list[str]]` |
| `roles` | Tools only: catalog |
| `is_active` | `True` on create |
| `added`, `modified`, `last_login` | ISO timestamps |
| `last_ip`, `language` | If you passed `ip` / `lan` |
| `index`, `irn`, `raw_id` | Present; do not construct these yourself |

### `get_entity(type, **kwargs) -> dict`

| `type` | Required kwargs |
|---|---|
| `"user"` | `user_id` |
| `"portfolio"` | `portfolio_id` |
| `"org"` | `portfolio_id`, `org_id` |
| `"team"` | `portfolio_id`, `team_id` |
| `"tool"` | `portfolio_id`, `tool_id` |

Missing kwargs → `500` `"Some parameters are missing"`. Missing row → `404`. Success → `document` is the entity.

```python
org = auc.get_entity("org", portfolio_id=pid, org_id=oid)
name = org["document"]["name"]  # after checking success
```

---

### `list_entity(type, **kwargs) -> dict`

| `type` | Required | Success `document` |
|---|---|---|
| `"org"`, `"team"`, `"tool"` | `portfolio_id` | `{ "items": [entity, …], "lastkey": … }` |
| `"portfolio"` | `user_id` | List of **rel-query envelopes**, not portfolio entities |
| `"app"` | `team_id` | Leftover; do not use |

Page size is 50; the controller does not take `limit`. Prefer the tree to list a user’s portfolios with names.

```python
tools = auc.list_entity("tool", portfolio_id=pid)
for item in (tools.get("document") or {}).get("items") or []:
    if item.get("handle") == "data":
        tool_id = item["_id"]
```

---

### `create_entity(type, **kwargs) -> dict`

Writes **one** entity. Does not create membership or grants.

| `type` | Required | Typical optional |
|---|---|---|
| `"user"` | `user_id` | `name`, `slot_a`, `email`, `ip`, `lan` |
| `"portfolio"` | — | `name`, `about`, `user_id` (→ `owner_id`), `tags` |
| `"org"` | `portfolio_id` | `name`, `handle`, `about`, `user_id`, `tags` |
| `"team"` | `portfolio_id` | `name`, `about`, `user_id`, `tags` |
| `"tool"` | `portfolio_id` | `name`, `handle`, `about`, `roles` (list), `user_id`, `tags` |

Also accepted on any type: `location`, `slot_b`–`slot_e`, `ip`, `lan`. `tags` must be a `dict` or stored as `{}`.

Success `document` is the created entity (new `_id` except users).

```python
created = auc.create_entity(
    "tool",
    portfolio_id=pid,
    name="Data",
    handle="data",
    roles=["viewer", "editor", "admin"],
    user_id=user_id,
)
tool_id = created["document"]["_id"]
```

---

### `update_entity(type, **kwargs) -> dict`

Same id kwargs as `get_entity`, plus **`payload`** (dict of fields to overwrite). Omitting `payload` raises `KeyError`.

- Entity missing, type `user` → `create_user_funnel` (upsert)
- Entity missing, other types → `400` `"Nothing to update."`
- `payload["tags"]` is sanitized
- On users, kwargs `name` / `slot_a` / `email` fill empty fields

```python
auc.update_entity(
    "org",
    portfolio_id=pid,
    org_id=oid,
    payload={"name": "Uptown", "tags": {"region": ["north"]}},
)
```

Success `document` is the full updated entity.

---

### `unlink_entity(**doc) -> dict`

Soft-delete. **In:** the full entity document from `get_entity` (spread as kwargs). After success, `get_entity` / `list_entity` no longer return it. Does **not** delete relationships.

```python
got = auc.get_entity("team", portfolio_id=pid, team_id=tid)
if got["success"]:
    auc.unlink_entity(**got["document"])
```

Prefer remove funnels when you also need edges cleared.

## 11. Relationships

Rel **item**: `{ "index": "<partition>", "rel": "<target id>" }`.

### `create_rel(reltype, **data) -> dict`

**In:** `reltype` from [§5.3](#53-relationships-how-they-attach) plus the kwargs in that table.

**Out:** envelope; `document` is `{index, rel}`. Idempotent overwrite if the edge already exists.

```python
auc.create_rel("user:team", user_id=ada, team_id=editors)
auc.create_rel("team:user", user_id=ada, team_id=editors)
auc.create_rel("team/tool:org", team_id=editors, tool_id=data, org_id=downtown)
```

Unknown `reltype` will fail when building keys (unbound `index`).

---

### `get_rel(reltype, **data) -> dict`

Same kwargs as create, including the **target** id. Success `document` is the rel item. Missing → `404`.

---

### `list_rel(reltype, **data) -> dict`

**In:** source ids only (no target), except invite types as in the catalog (`hash` for `hash:team`; `email:hash:ttl` lists the whole invite partition).

**Out:** `{ success, document: { "items": [ {index, rel}, … ], "lastkey": … }, status }`. Default max **50** items.

```python
listed = auc.list_rel("team:tool", team_id=editors)
tool_ids = [row["rel"] for row in listed["document"]["items"]]
```

---

### `delete_rel(reltype, **data) -> dict`

Same kwargs as `create_rel`. For `hash:team`, the implementation expects `team` not `team_id` — prefer not to delete that type until aligned.

**Out:** envelope; `document` is the key that was deleted.

## 12. Queries over the graph

### `user_portfolios(user_id) -> list[str]`

**In:** `user_id`.

**Out:** unique `portfolio_id` strings (may be empty). Walks `user:team` then `team:portfolio`. Not an envelope.

```python
for pid in auc.user_portfolios(user_id):
    ...
```

---

### `is_user_team_same_portfolio(*, user_id, team_id) -> bool`

**Out:** `True` if some portfolio of `user_id` also contains `team_id` (`team:portfolio`).

---

### `is_user_team_org_same_portfolio(*, user_id, team_id, org_id) -> bool`

**Out:** `True` if that is true **and** the org entity exists under that portfolio.

Used by `assign_team_orgs`. Grant HTTP for `team/tool:org` does **not** call this.

---

### `get_team_users(*, user_id, team_id) -> dict`

**In:** `user_id` must already be a member; `team_id` is not composed with portfolio.

**Out success:** `document` is `{ user_id: { "user_id", "name", "last", "email" }, ... }`.  
If the caller is not on the team → `400` `"User is not in this team"`. Missing user entities are skipped.

---

## 13. Grant helpers

These wrap `create_rel` / `delete_rel` and take `method` `"POST"` or `"DELETE"`. They do **not** call `refresh_tree()`; HTTP routes do.

### `assign_team_tools(*, team_id, tool_id, method) -> dict`

Rel `team:tool`. No catalog or same-portfolio check.

---

### `assign_team_tool_roles(*, team_id, tool_id, role_id, method) -> dict`

Rel `team/tool:role`. Empty `role_id` → `400`. On **POST**, if the tool entity has a non-empty `roles` catalog, `role_id` must be in it. Unsupported `method` → `400`.

```python
auc.assign_team_tool_roles(
    team_id=editors, tool_id=data, role_id="editor", method="POST"
)
```

---

### `assign_team_tool_orgs(*, team_id, tool_id, org_id, method) -> dict`

Rel `team/tool:org`. `org_id` may be `"_all"`. No same-portfolio check. HTTP POST also runs `initialize_extension` on the extension; this method does **not**.

---

### `assign_team_orgs(*, user_id, team_id, org_id, method) -> dict`

Legacy `team:org`. Checks `is_user_team_org_same_portfolio` first (`400` `"Org does not belong to portfolio"`). No `/_auth` route. **Not** used by `authorize` for org activeness.

---

## 14. Funnels

Success `document` is a **list of step envelopes**. Required keys missing → `400` `"Missing attributes"` where implemented.

### `create_user_funnel(**kwargs) -> dict`

**In:** same as `create_entity("user")` (`user_id` required).

**Out:** `document[0]` is the create-entity step. Usually invoked via `update_entity("user")` on 404.

---

### `create_portfolio_funnel(**kwargs) -> dict`

**Expect:** `user_id`, `name` (optional `about`, `ip`, `lan`, `tags`).

**Also:** team named `Admin`, `team:portfolio`, membership both ways.

**Not:** default org or tool.

```python
r = auc.create_portfolio_funnel(name="Acme", user_id=user_id)
pid = r["document"][0]["document"]["_id"]
admin_tid = r["document"][1]["document"]["_id"]
```

---

### `create_org_funnel(**kwargs) -> dict`

**Required:** `name`, `portfolio_id`. Sets `handle` with `generate_handle(name)` (uppercase letters and digits only, max 10; `"warehouse"` → `""`).

Does not grant team access; org stays inactive until `team/tool:org`.

---

### `create_team_funnel(**kwargs) -> dict`

**Required:** `name`, `portfolio_id`. **Expect `user_id`** as first member. Also writes `team:portfolio` and membership.

---

### `create_tool_funnel(**kwargs) -> dict`

Same as `create_entity("tool")`. HTTP additionally restricts names to a Data/Schd catalog **before** calling this.

---

### `add_user_to_team_funnel(*, user_id, team_id) -> dict`

Writes `team:user` and `user:team`.

---

### `remove_user_from_team_funnel(*, user_id, team_id) -> dict`

Deletes both membership edges. Does not refuse “remove yourself” (HTTP does).

---

### `remove_team_funnel(*, portfolio_id, team_id) -> dict`

Unlinks the team entity; removes `team:portfolio`, membership, and attempts `team:org`. Tool grants may remain. Missing team → `400` `"Team not found"`.

---

### `remove_tool_funnel(*, portfolio_id, tool_id) -> dict`

Unlinks the tool entity only. Grants may remain. Missing → `400` `"Tool not found"`.

---

### `remove_org_funnel(**kwargs) -> dict`

**Stub.** Returns success with empty `document` and does **not** delete the org.

---

## 15. Invites

### `invite_user(email, team_id, portfolio_id, sender_id, sender_profile=None) -> dict`

**This is the method to call** from HTTP or product code.

**In:** invitee email, destination team and portfolio, inviter `user_id`. Optional `sender_profile` dict (`name`, `slot_a`, `email`) if the inviter entity is sparse.

**Out:** **never** includes the invite code.

| Situation | Result message (success) |
|---|---|
| Email already in Cognito | Added to the team (and portfolio via that team); no email |
| Email not in Cognito | `"Invite has been sent out."` |

Failures: could not add / could not send (SES, missing `FROM_EMAIL` or console URL).

```python
auc.invite_user(
    "ada@example.com",
    team_id=editors,
    portfolio_id=pid,
    sender_id=inviter_id,
    sender_profile={"name": "Grace", "slot_a": "Hopper", "email": "grace@acme.test"},
)
```

---

### `invite_user_funnel(**kwargs) -> dict`

Low-level send path. **Required:** `email`, `team_id`, plus `portfolio_id`, `sender_id` for documents. Writes invite rels and sends SES. Success `document` **includes the hash** — do not return this envelope to browsers. Prefer `invite_user`.

---

### `invite_create_user_funnel(*, code, email, first, last, pass) -> dict`

**Unauthenticated accept.** Validates code + TTL, creates a confirmed Cognito user with that password, creates the user entity, attaches membership for valid invites.

| Failure | `status` |
|---|---|
| Missing keys | 400 |
| Email already in pool | 404 `"User already exists, sign in to access"` |
| Bad / unknown invite | 404 / 400 |
| Expired | 410 |

Does not return tokens; client should sign in.

Kwarg name is `pass` (the password).

---

## 16. Small helpers

### `generate_handle(name) -> str`

Uppercase `A-Z` and digits from `name`, max 10 characters.

```python
auc.generate_handle("Acme Building 12")  # "AB12"
```

---

### `generate_ttl(offset_min=0) -> int`

Unix timestamp `now + offset_min * 60`. Invites use `offset_min=1440` (24 hours). Compare invite TTL with `generate_ttl(0)`.

---

### `generate_numeric_hash(input_string, length=20) -> str`

SHA-256 of the string, interpreted as an integer, truncated to `length` decimal digits.

---

### `generate_invite_hash(email, ttl) -> str`

Six-digit code from `email + SECRET_KEY + ttl`. Used internally by invite funnels.

## 17. Recipes

### Gate an extension handler

```python
class ExportCsv:
    def __init__(self):
        self.AUC = AuthController(config=load_config())

    def run(self, payload):
        portfolio, org = payload["portfolio"], payload["org"]
        auth = self.AUC.authorize(portfolio, org, resource="tool", tool_id="data")
        if not auth["success"]:
            return auth
        # auth["roles"], auth["user_id"]
        ...
```

Or `@authorize(resource="tool", tool_id_param="extension")` on a method of a class that has `self.AUC`.

### Provision a tenant like `/_auth`

```python
uid = auc.get_current_user()
port = auc.create_portfolio_funnel(name="Acme", user_id=uid)
pid = port["document"][0]["document"]["_id"]
org = auc.create_org_funnel(name="Downtown Site", portfolio_id=pid, user_id=uid)
team = auc.create_team_funnel(name="Editors", portfolio_id=pid, user_id=uid)
# install tool + grants, then:
auc.refresh_tree()
```

### After assigning a tool to a team in an org

```python
auc.assign_team_tools(team_id=tid, tool_id=tool_id, method="POST")
auc.assign_team_tool_roles(team_id=tid, tool_id=tool_id, role_id="editor", method="POST")
auc.assign_team_tool_orgs(team_id=tid, tool_id=tool_id, org_id=oid, method="POST")
auc.refresh_tree()
```

HTTP POST of the org grant also runs the extension’s `initialize_extension` handler; calling the helper here does not.

### Load a tool by handle

```python
listed = auc.list_entity("tool", portfolio_id=pid)
for item in (listed.get("document") or {}).get("items") or []:
    if item.get("handle") == "schd":
        return item
```

`authorize(..., tool_id="schd")` resolves handle vs id from the **tree**, not from this list.
